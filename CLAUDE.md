# CLAUDE.md — RentRoll

RentRoll is a Next.js (App Router) + TypeScript + Tailwind + Supabase
app for landlords and tenants. No product features are implemented yet.
This file is permanent guidance for every Claude Code session working in
this repo — read it before writing code, not after.

## 1. Spec is source of truth

- Read the relevant file under `spec/**` before implementing a screen or
  behaviour — start at `spec/index.md`. Do not implement from memory,
  from a prior session's summary, or from the original source PDFs
  (not in this repo).
- Use stable IDs (`L-04`, `T-01`, `S-01`, `P-01`, and element IDs like
  `L04-BTN-REMIND`) in implementation notes, commit messages, and PRs so
  work can be traced back to an exact spec line.
- `spec/decisions.md` overrides `spec/product.md` / `spec/screens/**` —
  but **only** on the exact point a numbered decision (`D1`…`D17`)
  resolves. Everything else in those files still stands as written.
- An item marked `> OPEN:` anywhere in `spec/**`, or listed in
  `spec/decisions.md`'s "intentionally left open" section, is not
  resolved. Never let it silently become a product decision by
  implementing an assumption — stop and ask, or escalate.

## 2. Two global product rules (`spec/cross-cutting.md`)

1. **No message leaves the system unless the landlord explicitly presses
   Send.** The assistant drafts; it never dispatches. (`S-01`'s "Did you
   send it?" step is the enforcement point — never add a path that sends
   without it.)
2. **No tenant-facing screen may expose:** rent amounts (except the one
   approved exception — a tenant's own receipts, `T-05`), repair costs,
   another unit's data, or another tenant's data.

If a task appears to require breaking either rule, **stop and escalate
rather than implement it.**

## 3. Design system (`spec/foundations.md` A1)

- Use only the A1 tokens — `ink`, `body`, `muted`, `line`, `canvas`,
  `surface`, `primary`/`primary-soft`, `success`, `warning`, `danger`,
  `neutral`, the type scale, and the spacing/radius/shadow tokens.
  They're already wired into `tailwind.config.ts`.
- No raw hex values inside components.
- No arbitrary stock Tailwind colours (`text-blue-500`, `bg-red-600`,
  …). If a colour isn't one of the tokens above, that's a sign a token
  is missing, not a reason to reach for a one-off.

## 4. Component ownership (`spec/foundations.md` A2)

- The A2 component library (buttons, form fields, display components)
  lives in `src/components/ui`, built once, used everywhere by name.
- Feature lanes must not casually modify `src/components/ui` — it's
  shared, so a change there changes every screen using it.
- If a screen needs something the shared library doesn't have yet,
  build the minimum local version in that feature's own tree and mark
  it so it gets found and generalised later:

  ```
  // PROMOTE: <what this should become in src/components/ui, and why>
  ```

## 5. Money and dates

- Money: `₹` prefix, Indian digit grouping, no decimals. Use
  `formatRupees` from `src/lib/format.ts` rather than reimplementing it.
- Dates: `DD MMM YYYY` everywhere (`spec/foundations.md` A2, "Date
  field").

## 6. Tenant security boundary

- `src/app/(tenant)/**` is public, token-based, and must never import
  landlord-only server implementation from `src/server/landlord/**` —
  see `src/server/README.md`.
- Enforced by `eslint.config.mjs` (editor-time) and
  `scripts/check-boundaries.mjs` (authoritative — run via
  `npm run check:boundaries`, part of `npm run verify`). Both must stay
  green; don't work around a failure, fix the import.
- `spec/decisions.md` `D1` splits the tenant-facing token into
  `unit.door_token` and `tenancy.tenant_token`, each with different
  grants (see `D1`/`D2`). Once auth/schema work lands, "has a valid
  token" is not one permission — check which token type it is.

## 7. Testing

- Test behavioural and security-critical logic — boundary enforcement,
  rent/payment status derivation, permission checks — not styling or
  rendering.
- `npm run verify` (typecheck + lint + check:boundaries + test) must
  pass before pushing.

## Commit and PR conventions

Never add AI attribution to commits or pull requests in this
repository — no `Co-Authored-By`, no `Claude-Session` trailer, no
"Generated by Claude", no Anthropic attribution of any kind.

## Structure

| Path | What it is |
|---|---|
| `src/app/(landlord)/**` | Landlord workspace, sign-in required — `spec/screens/landlord/*.md` (`L-01`…`L-15`) |
| `src/app/(tenant)/u/[token]/**` | Public tenant link surface, no sign-in — `spec/screens/tenant/*.md` (`T-01`…`T-05`) |
| `src/app/dev/**` | Local-only routes; every page calls `assertDevOnly()` from `src/lib/dev-only.ts` |
| `src/server/landlord/**` | Server-only, landlord-only. Never imported from the tenant tree. |
| `src/server/tenant/**` | Server-only, tenant-surface implementation |
| `src/server/shared/supabase/**` | Supabase server/admin client factories (server-only) |
| `src/lib/supabase/client.ts` | Supabase browser client — safe for Client Components on either side |
| `src/components/ui` | The A2 shared component library (see §4) |

## Commands

`npm run dev` · `build` · `typecheck` · `lint` · `test` ·
`check:boundaries` · `verify` (typecheck + lint + check:boundaries + test).

## Out of scope until a schema ticket lands

No database schema exists yet, and none should be invented in feature
work. `spec/decisions.md` resolves the product-level conflicts a schema
needs answered, but the entity relationship diagram itself was never in
the source material this spec was converted from — see `spec/index.md`.
